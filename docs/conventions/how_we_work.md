It cost an hour: a flood over a grid of `-R .. R` by `-R .. R` refused every place it was asked about. **Index a new two-dimensional array from 0**, and when a small function that reads right gives a wrong answer, print the value just stored before doubting the reading. Seven arrays of the tree are declared so (`castle-chunks.adb:143`, `Castle.Water.View_Grid`, five in `tools/`); whether any is read wrongly was not looked into, and nothing was changed: the gate's two builds agree and pass with them.

*From the entry "His playtest notes of the storehouse" (in `stores.md`):*

  - **Run the reproduction again after the fix.** I took "Gatherers can't find berries even when they are close" for no room in the stockpile, mended that, and the same run showed every line unchanged: the cause was a bush being one gatherer's (and the band's reach). A fault is not mended until the run that showed it shows it gone; say plainly of a fault that was not reproduced that it was not (the builder stalled at the fence).
  - **A check that does not fail with the fix taken out says so.** `colony_check`'s made-up hillside passes with the old digging order; its comment says it does not catch the pit and names the tool that does. Prove a safety check by taking the guarded line out, on the terrain it was found on.

*From the entry "Foresters with no tree in reach, and paths straight or at 45 degrees" (in `band.md`):*

  - **A fault with no save of his to look at is made two ways: by playing on, and by where the stake is put.** `colony_run --tree-stats` (the trees standing by how far from the stake, each forester's hours by what its status said) showed the reference site's 60 m bare of trees by the band of thirteen's hundred and thirtieth day (nothing grows back), and a stake on open land with five. Run a new kind of "can't find X in reach" long, and on a stake away from the reference one, before calling it not reproduced.
  - **A test site made for one line is not a site for another**: the hillside stockyard's box was chosen for the 35-degree path, and at 45 degrees its stockyard is refused (the lot is square to the blocks; the storehouse has to stand within 2 m of the path: only a box with a corner at the path is taken, two of five on the flat, none of ten on that hillside). Read a failing site's log for "refused" before calling it a pit; the gate found this, not a run of mine.

- **When his game may be running** (he says so, or `pgrep -x castle_game` finds it): build only in a scratch copy (`rsync -a --delete --exclude obj --exclude bin --exclude .git`), never link in the working copy; a still is a short window from the scratch build, taken only when `pgrep` finds his game not running (a hidden display with software drawing takes minutes a still and all the cores). A check that passes in release has not run with index checks: run `colony_check` in debug before calling a pass gated.

*From the entry "Building and zoning, a pass after stage 6a" (in `housing.md`):*

  - **Never `pkill -x castle_game`**: John may have his own game running. Stop a window of mine by its task (it is started in the background or under `timeout`).
  - **Reproduce a fault he names before changing anything, and measure a fix on more than one run.** The eating fault was counted first (47 meals begun with a load on the reference band); its plain fix starved the housing run's first day (gatherers' own food went into the stores the cook holds), which the reference band alone did not show. The pad's first fix (the camp's turf allowance) broke three hillside checks. Neither was committed.
  - **"The grass stays in the air": cause not found, left at his word** (John, 2026-11-13, after the pass was merged: "I saw the grass going with the ground every other time, it seemed to have just happened on a couple of blocks, the gatherer had been collecting grass on the blocks before the plot began being built, maybe there is something there where the state of the grass has been modified but not completed and the grass remains? Just leave it for now, if I reproduce it again, I will try and recreate the exact conditions for debugging.") I had taken it for grass left over a hole dug under it (one way grass does float, now mended: the game's dig takes what grew on what it removes, and levelling and path laying cut what is left over a hole, `Cut_Plants`); his own reading is grass gathered on those blocks before the plot was begun. Whether `Cut_Plants` covers that is untested: don't chase it unasked. Scan blocks, not pixels, and make a test fault the way the player makes it (`--late --dig` one row: a dig before the ground is loaded sees no plants). To scan blocks from a save, `colony_run --load` and `Castle.World_Blocks.Block_At`.

- A change in behaviour, options, checks or a save format updates its system README (`docs/systems/`) in the same commit as the code. The main `README.md` changes when a system, a tool or the layout does. They are the reference.

- Colours come from the designer's palette in `Castle.Colors` (named hex codes from `docs/design/color_palette.txt`). The world's materials, texels and autumn colours use it; serf clothing, deer coats, props and the UI still have literals of their own (not converted yet). Use a palette name for any new colour; if none fits, add a derived entry there with the sum in a comment.

- Tuning constants live at the top of the relevant `.ads` (for example `castle-terrain.ads`, `castle-hydrology.ads`, `castle-buildings.ads`, `Castle.Deposits.Precious`).
